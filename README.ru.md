# HSBG Overlay — оверлей для Hearthstone Battlegrounds на macOS

Показывает поверх Hearthstone вероятность выигрыша текущего боя, последние
известные столы всех оппонентов, таблицу лобби, трекер пула миньонов и
статистику по твоим матчам.

Работает **только на чтение**: разбирает `Power.log`, который игра пишет сама.
Никакого чтения памяти процесса, инъекций или сетевого взаимодействия с игрой —
тот же механизм, на котором работают HSTracker и Hearthstone Deck Tracker.

<sub>**Прогноз — это симуляция, а не оракул.** Часть боевых триггеров всё ещё
не отыгрывается — [список](docs/ACCURACY.ru.md#что-не-смоделировано). Если такая
карта стоит на любом из столов, оверлей пишет это прямо на карточке шансов
(`точность ~85% · не смоделировано: <карты>`), а не выдаёт уверенное число,
за которое не может отвечать.</sub>

## Установка

Нужен macOS 12 или новее (Apple Silicon или Intel). Python 3.11+ нужен только
для запуска из исходников — `setup.sh` предпочитает 3.13
(`brew install python@3.13`), а собранное приложение несёт свой. Копируй блок
целиком:

```bash
git clone https://github.com/Dimus99/hsbg-overlay.git
cd hsbg-overlay
./setup.sh          # .venv с PyObjC — в систему ничего не ставится
./run.sh --check    # папка логов, язык игры, база карт, окно игры
./run.sh            # запустить оверлей
```

При первом запуске оверлей дописывает разделы `[Power]` и `[LoadingScreen]` в
`~/Library/Preferences/Blizzard/Hearthstone/log.config` — после этого
**перезапусти Hearthstone один раз**, чтобы игра начала их писать. В строке
меню появится значок **BG**: скрыть оверлей, включить кружки «?», включить
журнал отладки или выйти.

Разрешение на запись экрана **не требуется** — размеры окна берутся из
публичного списка окон. Единственная зависимость в рантайме — PyObjC; имена и
арт карт берутся с [HearthstoneJSON](https://hearthstonejson.com/) и кэшируются
на диск. Пошагово, с таблицей «если что-то не работает» —
**[docs/INSTALL.ru.md](docs/INSTALL.ru.md)**.

### Без терминала

```bash
./make_app.sh /Applications   # или просто ./make_app.sh — соберёт в dist/
```

**HSBG Overlay.app** (~23 МБ) несёт внутри свой Python, PyObjC и код оверлея,
так что не зависит ни от этой папки, ни от `.venv`: перетащи в Dock или скопируй
на другой Mac. Двойной щелчок открывает окно с кнопкой **Запустить /
Остановить**, кнопкой **Проверить окружение** и живым хвостом журнала — упавший
запуск видно сразу, а не «ничего не произошло». Оверлей работает отдельным
процессом, поэтому окно можно закрыть, а потом открыть снова и остановить его.
То же окно доступно и без сборки: `./run.sh --launcher`.

Подпись — ad-hoc: для своего Mac достаточно. Скачанное с другого компьютера
приложение macOS держит в карантине, пока не снимешь флаг:

```bash
xattr -cr "/Applications/HSBG Overlay.app"
```

Вывод пишется в `~/Library/Logs/HSBG-Overlay.log`. Настройки и кэш карт — в
`~/Library/Application Support/hsbg-overlay/`, они общие у приложения и у
запуска из терминала. Сборку описывает `packaging/hsbg.spec` (PyInstaller,
`make_app.sh` ставит его сам), точка входа — `packaging/entry.py`, иконку рисует
`tools/appicon.py`.

## Что показывает

| | |
|---|---|
| **Шансы боя** | победа / ничья / поражение по Monte-Carlo симуляции реальных столов, с ожидаемым и максимальным уроном, доверительным интервалом и риском смертельного исхода — плюс отметка о точности, если на столе есть триггер, который движок не разобрал |
| **Столы оппонентов** | каждый стол, который показали в этом матче, — самими картами и со статами, с которыми миньоны шли в бой |
| **Таблица лобби** | все 8 игроков: место, здоровье, уровень таверны |
| **Пул миньонов** | сколько копий карты осталось в общем пуле и сколько уже стоит на чужих столах |
| **Твоя статистика** | среднее место, винрейт боёв, результаты с героем, которым играешь сейчас |
| **Бои этого матча** | все бои с фактически полученным уроном |

## Это вообще законно?

Оверлей читает `Power.log` — файл, который игра пишет сама, тот же самый, что
десять лет читают HSTracker и Hearthstone Deck Tracker. В игру ничего не
пишется, память процесса не трогается, пакеты не шлются, ввод не
автоматизируется: это окно, нарисованное рядом с игрой, и оно физически не
может ничего за тебя нажать.

То есть это та же категория, что и привычные трекеры, а не бот. Гарантией для
чьего-то аккаунта это не является — правила Blizzard трактует Blizzard, и
запускаешь ты на своё усмотрение.

## Интерфейс

Четыре независимых окна вместо одной длинной панели — у каждого своя роль.

![Панели оверлея](docs/screenshots/ru/panels.png)

*Середина матча со всем развёрнутым: таблица лобби, все увиденные столы
оппонентов, своя статистика и бои этого матча. Любой блок сворачивается кликом.*

**Главная плашка** — маленькая, в углу окна игры, всегда на экране. Во время боя
показывает `Бой · победа 62%`, в остальное время — ход, здоровье и уровень
таверны. Кнопка **▾ / ▸** сворачивает и разворачивает *всё остальное*, состояние
запоминается между запусками.

**Шансы** появляются сверху по центру окна игры — там, где и так смотришь во
время боя, — и только во время боя.

Внутри: полоса победа/ничья/поражение, ожидаемый и максимальный урон,
доверительный интервал, риск смертельного исхода и отметка о точности, если на
столах есть немоделированные карты. Вне боя ничего не считается — процессор во
время закупки свободен. Между меткой начала боя и первой атакой игра ещё только
выкладывает стол оппонента в лог: на это время на месте шансов стоит бегунок с
именем соперника той же ширины, а не цифры прошлого боя.

Плашка гаснет **по твоему первому действию в таверне**, а не по признаку из
лога: Hearthstone сбрасывает весь бой в лог одним куском (0.3–1.8 секунды,
замерено на девяти боях подряд) и только потом его анимирует, а первый реальный
клик игрока приходит через 20–84 секунды. Страховка — 60 секунд
(`combat_hold_seconds`). Конец *матча* — отдельный сигнал, он читается из
`LoadingScreen.log` (`GAMEPLAY` → `BACON`): ушёл со сцены матча — гаснут шансы,
кружки «?» и счётчик хода, а не висят поверх меню Battlegrounds.

**Сворачиваемые блоки** — под главной плашкой. Клик по заголовку сворачивает
блок, состояние сохраняется.

| Блок | Что в нём |
|---|---|
| **Выбор героя** | появляется только на выборе: каждый герой с твоим средним местом по нему и глобальным, если настроен внешний источник |
| **Таблица лобби** | все 8 игроков: место, здоровье, уровень таверны |
| **Столы оппонентов** | список — кого видели, сколько у них миньонов и когда; строки с сохранённым столом помечены значком из трёх полосок справа, наведи на такую — покажем стол |
| **Статистика** | твоё среднее место, винрейт боёв, результаты с текущим героем |
| **Бои этого матча** | история боёв с фактическим уроном |

**Всплывашки по наведению** появляются у курсора и ничего не занимают на экране
постоянно. Наводишь на героя — в таблице лобби оверлея *или на портрет игрока в
самой игре* — и всплывает его последний стол **самими картами**, как он выглядел
в начале боя; поверх картинок нарисованы живые атака и здоровье из лога (на
карте напечатаны базовые числа, а важны те, с которыми миньон реально дрался).
Наводишь на миньона в таверне — всплывает, сколько копий этой карты осталось в
общем пуле, сколько уже замечено на чужих столах, и текст карты.

Картинки — «сырой» арт с HearthstoneJSON в своей рамке: готовые рендеры карт
покрывают только старые сеты (из 13 миньонов текущего матча 11 отдавали 404), а
своя рамка заодно позволяет положить живые статы туда, где они читаются. Всё
кэшируется на диск.

Hearthstone не пишет наведение мыши в лог, поэтому наведение **в самой игре**
определяется по положению курсора относительно окна. Раз зону не видно, поверх
рейки портретов можно включить маленькие кружки **«?»** — по одному на слот.
Кружок и есть точка наведения: синий — стол этого игрока у нас есть, серый — ещё
не видели, золотой — курсор сейчас на нём. Нет кружка — нет и наведения. **По
умолчанию их нет** (они рисуются поверх чужой картинки — игры); переключатель —
пилюля **«? вкл / ? выкл»** в шапке блока «Таблица лобби» и пункт меню значка
**BG** (`show_hover_marks`). Кружки живут отдельно от панелей, так что
сворачивание оверлея их не убирает — свернуть и оставить кружки это и есть
основной способ смотреть чужие столы, не загораживая игру.

Если кружки не совпадают с портретами, запиши зону по двум углам:

```bash
./run.sh --tool calibrate -- --set leaderboard
```

Без `--set` инструмент просто показывает долю под курсором. Значения можно
положить в `settings.json` и руками:

```json
"extra": {"hover_zones": {"leaderboard": [0.0, 0.09, 0.085, 0.96],
                          "tavern":      [0.20, 0.215, 0.80, 0.42]}}
```

Наведение на строки в самом оверлее работает точно и калибровки не требует.

## Насколько точен прогноз

Симулятор **точно** моделирует всё, что есть в логе: атаку, здоровье,
Божественный щит, Провокацию, Яд/Отраву, Возрождение, Вихрь, порядок атак, выбор
целей и урон герою. Снимок обоих столов берётся прямо перед первой атакой,
поэтому все эффекты начала боя — способности героя, аксессуары, Rally, ауры —
уже вшиты в статы. Всё, чего в логе нет (предсмертные хрипы, Rally, Месть,
Ярость, ауры над другими триггерами), извлекается автоматически из английского
текста карт.

Замерено на 206 реальных боях из записанных логов:

| Метрика | Результат |
|---|---|
| Угадан наиболее вероятный исход | 79.1% |
| Brier score вероятности победы | 0.132 (0.25 — монетка) |
| Средняя ошибка по урону | 2.0 |
| Покрытие карт | 97% |
| Боёв разобрано **полностью** | 168 из 206 |

Прогноз считается около половины секунды против 8–40 секунд анимации, в покое оверлей
занимает 2–3% одного ядра. Если на столах есть карта с неразобранным боевым
триггером, на карточке шансов появляется `точность ~85% · не смоделировано:
<карты>` — тогда к проценту стоит относиться с большим подозрением. Перемерить
на своих логах:

```bash
./run.sh --tool accuracy
```

Что именно смоделировано, а что нет, как это измеряется и что нашли инструменты
отладки: **[docs/ACCURACY.ru.md](docs/ACCURACY.ru.md)**.

## Настройки

`~/Library/Application Support/hsbg-overlay/settings.json` (создаётся при первом
запуске):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `iterations` | 2000 | симуляций на прогноз |
| `sim_workers` | 0 (авто) | процессов под симуляцию |
| `sim_time_budget` | 2.5 | секунд; лучше меньше итераций, чем выйти за бюджет |
| `combat_hold_seconds` | 60 | страховка, через сколько прячутся шансы |
| `language` | `auto` | `auto` / `ruRU` / `enUS` / любая локаль HearthstoneJSON; задаёт и имена карт, и подписи самого оверлея |
| `anchor` | `top-left` | к какому углу окна игры крепиться |
| `offset_x`, `offset_y` | 16 | отступ от края |
| `overlay_opacity` | 0.88 | прозрачность |
| `overlay_scale` | 1.0 | масштаб |
| `show_opponents`, `show_leaderboard`, `show_pool`, `show_stats` | `true` | какие данные собирать |
| `show_when_hs_inactive` | `false` | держать оверлей на экране, даже когда Hearthstone не в фокусе или вовсе не запущен |
| `show_hover_marks` | `false` | кружки «?» на портретах оппонентов в игре |
| `extra.hidden` | `false` | свёрнут ли оверлей до главной плашки |
| `extra.collapsed` | `{}` | какие блоки свёрнуты |
| `extra.hover_zones` | — | калибровка зон наведения в игре |
| `offline` | `false` | не ходить в сеть (нужен прогретый кэш карт) |
| `debug_log` | `false` | писать журнал боёв |

Язык определяется автоматически, и на нём же оверлей пишет свои подписи.
Источники по убыванию достоверности: строка `SetLocale:` в начале
`Hearthstone.log`, выбранный язык текста в `.product.db` Battle.net, язык самого
Battle.net, локаль оболочки. При смене языка игры править ничего не нужно —
достаточно перезапустить оверлей. Внутренне всё привязано к `cardId`, который от
языка не зависит; свои подписи живут в `hsbg/i18n.py`.

**Внешняя статистика.** Публичные сайты со статистикой Battlegrounds (HSReplay,
Firestone) закрыты Cloudflare-защитой от ботов и не имеют открытого API, поэтому
по умолчанию внешний источник не настроен, и статистика — в том числе подписи под
героями на выборе — считается из твоих собственных логов. Если есть подходящий
источник, добавь в `settings.json`:

```json
"extra": { "stats_url": "https://example.com/bgs-heroes.json" }
```

Ожидаемый формат:

```json
{"heroes": [{"cardId": "TB_BaconShop_HERO_93", "averagePlacement": 4.21, "games": 12045}]}
```

## Инструменты разработки

```bash
./run.sh --tool replay     -- --combats --sim   # разобрать лог, показать столы и прогнозы
./run.sh --tool accuracy   -- --iterations 800  # измерить точность на своих логах
./run.sh --tool preview    -- --combat 5        # показать оверлей по записанному матчу
./run.sh --tool divergence -- --min-swings 2    # сверить движок с ходами самой игры
./run.sh --tool debugreview -- --boards         # прочитать журнал боёв
./run.sh --tool calibrate                       # подобрать зоны наведения в игре
./run.sh --headless                             # без окна, вывод в консоль
```

## Как это устроено

```
hsbg/
  logfiles.py    поиск и слежение за логами игры: Power.log и LoadingScreen.log
                 (переживает перезапуск игры)
  powerlog.py    токенизатор лога -> поток событий + таблица сущностей
  gamestate.py   состояние лобби: столы, лидерборд, история боёв
  carddb.py      база карт HearthstoneJSON + извлечение механик из текста
  sim/           движок боя, реестр эффектов, Monte-Carlo раннер
  pool.py        трекер пула миньонов
  stats.py       статистика из локальных логов + опциональный внешний источник
  i18n.py        подписи интерфейса на языке, в котором запущена игра
  ui/            окна AppKit, отрисовка, определение зон под курсором
  app.py         связывание потоков: лог + сцена -> состояние -> симуляция -> оверлей
  launcher.py    окно с кнопкой запуска: стартует и гасит оверлей, тянет журнал
```

Ключевая деталь разбора: во время боя игра копирует стол оппонента под
«призрачного» игрока (того, чей `GameAccountId` нулевой) — туда же попадают
миньоны таверны. Различить их можно только по тому, какие сущности созданы
внутри блока начала боя; именно так и определяется состав противника.

## Тесты

```bash
./.venv/bin/python tests/test_sim.py        # без зависимостей сверх venv
./.venv/bin/python -m pytest tests -q       # те же проверки под pytest
```

Набор покрывает движок боя, извлечение эффектов из текста карт, парсер лога,
определение языка и подписи интерфейса на обоих языках. Работает без базы карт и
без сети — проверки, которым нужен HearthstoneJSON, сами пропускаются на холодном
кэше.
